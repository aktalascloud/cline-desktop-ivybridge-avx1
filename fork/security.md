# Security qualification

Reviewed 2026-11-04 against the [upstream security page](https://github.com/cline/cline/security), current npm advisories and a refreshed RustSec database. This fork is unofficial; installed approval policies and user data remain intact.

- [Hub dashboard cross-origin access](https://github.com/cline/cline/security/advisories/GHSA-3cj3-hqcr-g934): review the current dashboard origin-authorization boundary, not the obsolete unauthenticated implementation. The fork also requires a Hub token; installed missing/wrong-token probes deny upgrades and an authenticated read succeeds. MCP OAuth keeps issuer/client binding, PKCE/state and configured-header origin boundaries.
- [Old Kanban server](https://github.com/cline/cline/security/advisories/GHSA-5c57-rqjx-35g2): the bundled CLI does not start that obsolete server. A separately installed Kanban product is outside this package and its security claims.
- [Compromised npm CLI 2.3.0 publish](https://github.com/cline/cline/security/advisories/GHSA-9ppg-jx86-fqw7): this installer builds CLI JavaScript from the pinned source and embeds verified prebuilt Bun; it does not install that npm release.

Compatible dependency fixes include gRPC, Hono, Azure Identity/MSAL, proxy-addr, body-parser, qs, redirects, Markdown/link parsing, image parsing and development tooling. Zod 4 is updated; the MIT legacy Zod 3 patch rejects oversized bounded arrays/sets before visiting their elements. Regression checks exercise both versions.

Workspace npm audit warnings decreased from 33 package names to 12. Remaining reports include legacy development/download tools, optional telemetry integrations and version-based findings on locally patched Zod 3. They are retained as findings, not silently ignored. No claim of a vulnerability-free dependency tree is made. The pinned-lock RustSec `vulnerabilities` bucket is empty, but four `unsound` and four `unmaintained` informational warnings remain. The refreshed Windows dependency-source review found no application or dependency call to the affected anyhow 1.0.102 `Error::downcast_mut` API (RUSTSEC-2026-0190); other `downcast_mut` uses belong to std::any or other crates. Tokio 1.49.0 remains version-flagged (RUSTSEC-2026-0386), but its affected Unix `AsyncFd` constructors are not compiled on Windows. The other six informational warnings are outside the Windows normal/build graph. These are scoped target/call-site findings, not proof of all-runtime safety; no warning is suppressed. Dependency-version remediation remains tracked. This is not a clean native-security verdict. See the latest qualification for actual coverage and limitations.

The remaining npm dependency paths were classified on 2026-11-02: Jaeger, old uuid, FTP/ZIP browser downloads and Zod 3.23.8 belong to the legacy VS Code tree; Vitest/mocker/tinypool warnings concern older development/Storybook trees. Current SDK tests use Vitest 4.1.12. Older OpenTelemetry core also remains through OTLP HTTP exporters, while runtime telemetry is opted out; no Baggage extraction call was found in reviewed Desktop/Core telemetry code. Deepmerge and glob/minimatch warnings remain in theme/design/build/test dependencies. This classification does not establish every transitive JavaScript call path as unreachable and does not justify cross-major blanket overrides.

Every release requires package/source privacy review, updater signature and tamper rejection, exact installed payload checks and a data-preserving update. Authenticode is NotSigned. GUI and repeat EXE downloads are excluded by the owner; server digest/size, source tag and signed feed are checked instead. Never publish credentials, local configuration or session data.

The 1.0.16 candidate additionally removes upstream provider-request debug capture (#15459). Fresh RustSec data also flags yanked async-executor 1.14.0 outside the unchanged Windows normal/build graph; no vulnerability advisory is attached to that yanked notice. Existing informational findings remain visible. Authenticated Hub provider commands reject tokenless transports, track accepted writes during drain, and never replay dispatched settings mutations after a lost response.
